# Решения, принятые без владельца

С 07.11.2026 три модуля (перевод, улучшение сканов, раскраска) делаются без ожидания ответов.
Если что-то неясно, Claude выбирает сам и записывает решение сюда: что решено, почему и что
придётся переделать, если владелец решит иначе. То, что без владельца не сделать, — в `FOR_ME.md`.

Решения до 07.11.2026 — в таблице `PLAN.md`.

## Общее

- **Где лежат файлы.** `DECISIONS.md` и `FOR_ME.md` — в `plus/`, рядом с `PLAN.md`: весь наш код
  и документы живут в `plus/`.
- **Ветки.** Общая основа — ветка `relad/core` от `main`. Модули — `relad/translate`,
  `relad/enhance`, `relad/colorize`, каждая от `relad/core`. В `main` ничего не вливаю: это
  решение за владельцем (порядок — в `FOR_ME.md`). Ветки отправляю на GitHub, чтобы они не
  жили только на одном компьютере.
- **Список «15 пунктов» не пришёл.** В сообщении вместо него стоял текст «[список из 15 пунктов]».
  Архитектуру строю с учётом идей из `PLAN.md`: чтение по кадрам, глоссарий, правки сообщества,
  редкие языки, пересказ, персонажи, сервер и подписка, легальные источники. Если в списке
  есть что-то ещё, проверю архитектуру, когда список придёт.
- **M1 заменён веткой основы.** План M1 от 06.11 (экран, настройки, доступ к странице, слой)
  остаётся, но делается в объёме, который нужен трём модулям.
- **Главный механизм — обработка картинки страницы, а не слой поверх.** Все три функции
  устроены одинаково: «взять картинку страницы → получить новую картинку». Перевод рисуется
  прямо на копии страницы поверх оригинала, улучшенная и раскрашенная страница заменяют
  исходную. Почему:
  - приближение, прокрутка, режимы «страницы» и «лента» работают сами, ничего не съезжает;
  - не зависит от того, как Mihon рисует страницу (переживёт его будущий рендерер);
  - один кеш и одна очередь для всех трёх функций, функции можно сочетать
    (раскрасить → улучшить → перевести).

  Минус: на переведённой странице нельзя нажать на облачко и увидеть оригинал. Для этого
  позже добавим слой поверх страницы, данные для него (области и тексты) сохраняются уже сейчас.
- **Страница показывается сразу.** Сначала открывается оригинал, обработанная версия
  подменяет его, когда готова. Поэтому медленный перевод или улучшение не задерживают чтение.

## Основа (ветка `relad/core`)

- **Конвейер.** Шаги идут по порядку: раскраска → улучшение → перевод. Раскрашиваем
  до увеличения, потому что облачная раскраска отдаёт картинку ~1000 px и дешевле на маленькой
  странице. Переводим последним, чтобы текст рисовался на финальной, самой чёткой странице.
- **Кеш каждого шага отдельно** (300 МБ, старые удаляются первыми). Выключил перевод — сразу
  видна улучшенная страница, без повторной обработки.
- **Очередь «новые первыми».** Страница, которую открыли последней, — та, на которую смотрят.
  Ждут не больше 6 задач, лишние отбрасываются и запрашиваются снова, когда страница
  откроется. Одновременно — 2 задачи.
- **Ошибка не повторяется минуту** (или до смены настроек), чтобы глава без ключа API не слала
  запросы по кругу. Ошибка видна всплывающим сообщением, не чаще раза в 10 секунд.
- **Анимированные страницы (GIF, анимированный WebP) не обрабатываются.** Их нельзя
  перерисовать без потери анимации.
- **Свой HTTP-клиент для ИИ, не клиент Mihon.** В подробном сетевом журнале Mihon печатаются
  заголовки запросов, а в них ходят ключи Gemini и Claude. Плюс куки и кеш Mihon — для сайтов
  манги, ИИ они не нужны.
- **Ключи API — в Android Keystore (AES-GCM), в закрытой настройке.** В бэкап Mihon не
  попадают; системный бэкап на другой телефон их не расшифрует. У TachiyomiAT ключи лежали
  открытым текстом и попадали в бэкап.
- **Три формата API без SDK:** OpenAI Chat Completions (OpenAI, OpenRouter, локальные серверы),
  Gemini `generateContent`, Anthropic Messages. Официальные REST API, никаких
  неофициальных адресов. TachiyomiAT использовал неофициальный `translate.google.com`
  и архивированный SDK Gemini.
- **В запросы OpenAI-формата не отправляются `temperature`, `max_tokens` и `response_format`.**
  Новые модели OpenAI отвергают часть из них, многие модели OpenRouter — остальные. Формат
  ответа описывается в самом запросе, JSON достаётся из ответа даже с лишним текстом вокруг.
- **Claude: запасная модель при отказе.** Новые модели Claude (Opus 5.5, Opus 5, Sonnet 5.5,
  Fable 5.1) могут отклонить запрос своими фильтрами безопасности (ответ 200 со
  `stop_reason: "refusal"`). На API Anthropic таким моделям добавляется `fallbacks: "default"`
  (бета `server-side-fallback-2026-07-01`): отклонённый запрос сам перезапускается на модели,
  которую Anthropic советует для этого вида отказа. Для прокси и других моделей не добавляется.
  Если отказали все — пользователь видит «Claude отклонил запрос (категория)», а не «пустой ответ».
- **Модели в провайдере не выбраны заранее.** Пользователь пишет ID модели сам: список моделей
  меняется каждый месяц, а зашитое в код быстро устаревает (у TachiyomiAT по умолчанию стояла
  уже отключённая `gemini-1.5-pro`).
- **Функции включаются глобально, не для каждой манги.** Включение по манге и быстрый
  переключатель в читалке — следующий шаг, данные для этого готовы.
- **Тестовая манга — синтетическая** (`plus/tools/test-manga`), чтобы не было вопросов
  с авторскими правами.

## Улучшение сканов (ветка `relad/enhance`)

**Что было у mihon_img_upscale и что у нас лучше:**

| У них | У нас |
|---|---|
| Модели внутри APK, APK 246 МБ | Ни одной модели в APK: скачиваются при первом использовании (4 × 2,6 МБ), с проверкой SHA-256 |
| Встроенная некоммерческая модель (2x-sudo-UltraCompact, CC-BY-NC-SA) | Только MIT (Real-CUGAN). Некоммерческие модели — только по явному согласию пользователя и никогда в платной версии (переключатель появится, как только такая модель будет в списке) |
| Одна сила обработки на всё | Сила очистки выбирается для каждой страницы по тому, как сильно сжат её JPEG; плюс «белая бумага» |
| Модели и SDK лежали у автора на компьютере, сборку не повторить | Всё скачивается из официальных источников по закреплённым версиям с хешами; сборка повторяется на CI |
| Библиотека Qualcomm (67 МБ) с отзываемой лицензией, NNAPI | ncnn + Vulkan: работает на всех видеочипах (Mali, Xclipse в Exynos, Adreno), без NPU-библиотек; без Vulkan — на процессоре |
| 118 изменённых файлов Mihon, посторонние функции | Ни одного нового изменения в файлах Mihon: модуль `plus/enhance` подключается через общий конвейер |

**Сравнение моделей (07.11, `plus/tools/enhance-bench`).** Владелец посмотрел первую версию
(waifu2x) и написал, что сканы «не стали сильно лучше, есть текстура». Он прав. Сравнили
8 вариантов на странице, похожей на мангу (растр, штриховка, линии скорости, мелкий текст), в трёх
«сканах»: просто маленький (JPEG 80 %), плохой (JPEG 30 %, шум), очень плохой (JPEG 12 %, серая
бумага, зерно).

| Модель | Лицензия | Итог |
|---|---|---|
| waifu2x CUnet, шумоподавление 1 и 3 | MIT | На плохих сканах почти как простое растягивание: квадратики JPEG и серая бумага остаются. Это и была «текстура» |
| **Real-CUGAN se ×2** (conservative, denoise1x/2x/3x) | MIT | Лучший: белая бумага, чёткие линии и текст. Сильная очистка сглаживает растр, поэтому сила выбирается по странице |
| Real-CUGAN pro ×2 | MIT | Чуть мягче se, преимуществ нет |
| Real-ESRGAN animevideov3 ×2 | BSD-3 | Чёткий, но рисует муар на растре и оставляет серый фон |
| Real-ESRGAN x4plus anime 6B | BSD-3 | **Портит буквы и дорисовывает штриховку, которой нет.** В 20 раз медленнее. Не берём — и в облаке тоже |

**Решения:**
- **Модель — Real-CUGAN se ×2 (bilibili, MIT)**, четыре силы: Бережно / Слабо / Средне / Сильно.
- **«Авто» (по умолчанию): сила по качеству JPEG.** Качество читается из таблицы квантования
  файла (то же, что пишет libjpeg): меньше 25 % — сильно, 25–50 % — средне, 50–75 % — слабо,
  больше — бережно. PNG — бережно, WebP с потерями — слабо. Оценка шума по самой картинке не
  работает: растр похож на шум, а сильный JPEG шум как раз стирает, оставляя квадратики.
  Слабое место: если плохой скан пересохранили в хорошем качестве, «авто» его недооценит —
  тогда пользователь выбирает силу сам.
- **«Белая бумага» (по умолчанию включена):** до нейросети серая/жёлтая бумага растягивается
  до белой (каждый цветовой канал отдельно), как делают сканлейтеры уровнями. Только для
  чёрно-белых страниц: цветные, тёмные и уже белые не трогаем.
- **Общие SE-признаки для кусочков.** Real-CUGAN усредняет признаки по всей картинке; если
  кусочки считать отдельно, тон «прыгает» от кусочка к кусочку. Сначала прогоняем все кусочки
  до последнего SE-блока, усредняем (с весом по площади), потом считаем каждый кусочек с этими
  общими значениями. Способ realcugan по умолчанию (пробные кусочки 32 px) на эмуляторе сделал
  чистую страницу блёклой — проверили и заменили. Наш способ совпадает с обработкой целой
  страницы (отличие ~4 из 255, на глаз не видно), стоит ~1,5 обычного прогона.
- **Своя реализация на C++** (`upscaler_jni.cpp`), схема кусочков — как в realcugan-/waifu2x-ncnn-vulkan
  (MIT, указано в шапке). Кусочки 200 px с запасом 18 px, края страницы отражаются.
  Предобработка — на процессоре средствами ncnn, на видеочипе — только сама сеть.
- **ncnn 20260526, а не самая свежая 20261020:** свежая собрана новым NDK и не собирается с
  NDK 29, который ставит Android Gradle Plugin. ncnn скачивается при сборке с проверкой хеша
  (40 МБ, в репозиторий не кладём). NDK 29 поставлен автоматически.
- **Страницы больше 2200 px по длинной стороне не увеличиваются** (настройка: 1600 / 2200 / 3000):
  они и так чёткие, а ×2 от них — 4400 px и большой расход памяти.
- **Одна страница за раз** на видеочипе, загруженная сеть держится между страницами. Старые
  скачанные модели (waifu2x из первой версии) удаляются сами.
- **Проверено на эмуляторе** (глава 3 тестовой манги, 4 вида плохих сканов): все страницы
  стали ×2, бумага белая (серая 237 → 255, жёлтая 229/223/206 → 254), линии и текст чёткие,
  растр на хороших сканах сохранён, швов нет. Сравнение — `plus/tools/enhance-bench`.
  **Скорость на эмуляторе не показательна:** у него одно ядро и программный видеочип
  (2–4 минуты на страницу). Тот же расчёт на Mac занимает 1,6 с. Скорость надо мерить на телефоне.
- **Размер APK:** +10 МБ на архитектуру (выпускной arm64: 27 → 37 МБ). Почти всё — ncnn
  вместе с компилятором шейдеров glslang. Позже можно собрать ncnn только с нужными слоями
  (обычно 2–3 МБ).

**Улучшение через API (просьба владельца от 07.11: «нужен выбор улучшение через api»).**
Исследовали облачные сервисы: Replicate, fal.ai, Stability, Recraft, Topaz, Clipdrop,
Cloudflare. Выбор:
- **Replicate**, официальный HTTP API без SDK. На нём есть почти любая модель, включая
  Topaz. Пользователь вводит свой токен (хранится зашифрованным, как ключи ИИ), выбирает
  модель. Поток: загрузить страницу как файл → создать задачу с ожиданием до минуты →
  опрашивать, если дольше → скачать результат → удалить загруженный файл.
- **Модели-заготовки:** Real-ESRGAN x4plus (BSD-3, ≈ $0,004 за страницу) и Topaz Labs
  (проприетарная, ≈ $0,05), плюс «другая модель» (любая `владелец/название[:версия]`, поле
  картинки и параметры JSON). Версия Real-ESRGAN закреплена, чтобы автор не подменил модель.
- **По умолчанию — телефон, не облако.** Real-ESRGAN, который есть у всех облачных сервисов,
  мы проверили той же сравнивалкой: x4plus превращает растр в штриховку и портит мелкие
  буквы, anime 6B дорисовывает несуществующее. Real-CUGAN на телефоне чище. Облако полезно на
  слабом телефоне или с платной моделью (Topaz не проверен — нужен токен, см. FOR_ME).
- **fal.ai не взяли первым:** в их условиях запрещено «выставлять API напрямую конечным
  пользователям» — для приложения с ключом пользователя это спорно. Stability: картинка до
  1 МП (страница не влезает) и генеративная. Recraft: можно добавить позже как ещё одну заготовку.
- **Токен уходит только на сервер Replicate и его файловый хост** (`*.replicate.delivery`);
  если модель вернёт ссылку на другой сервер, файл скачивается без токена.
- «Белая бумага» делается на телефоне до отправки; остальная обработка — в облаке.
- **Проверено:** 7 тестов с поддельным сервером внутри теста и эмулятор с поддельным
  Replicate (`plus/tools/fake-ai/fake_replicate_server.py`): проверка токена, 4 страницы
  главы 3 прошли весь путь, опрос статуса, удаление файлов. **Настоящий Replicate не проверен**
  (нужен токен).

## Перевод страницы (ветка `relad/translate`)

**Что было у TachiyomiAT и что у нас лучше:**

| У них | У нас |
|---|---|
| Только скачанные главы | Онлайн, скачанные и локальные: перевод встроен в конвейер страниц |
| Неофициальный `translate.google.com`, Gemini через архивированный SDK, отключённая модель по умолчанию | Официальные API (OpenAI-совместимые, Gemini, Claude), модель выбирает пользователь |
| Поиск текста ML Kit, примитивная группировка, эффекты из одного символа выбрасываются | Одна мультимодальная модель находит облачка, подписи, звуковые эффекты (и односимвольные) и надписи на рисунке, понимает вертикальный японский |
| Перевод строк по отдельности, без контекста | Вся страница целиком плюс переводы двух прошлых страниц главы, чтобы имена и термины не скакали |
| Белый прямоугольник поверх текста | Стирается только текст внутри облачка: заливка фона облачка, контур и рисунок не трогаются |
| Шрифты Blambot без лицензии, без казахских букв и узбекского ʻ | Комиксный Shantell Sans (OFL, можно в платном приложении) с казахскими буквами; системный шрифт там, где в нём нет букв (CJK, тайский, арабский) |
| ML Kit не умеет узбекский и казахский | Любой язык, который знает модель; для узбекского и казахского — отдельные указания по алфавиту |
| Ключи открытым текстом в бэкапе | Ключи зашифрованы и в бэкап не попадают (см. «Основа») |

**Решения:**
- **Один запрос на страницу.** Модель возвращает JSON: тип области, рамку (0–1000, как привык
  Gemini), оригинал, перевод. Отдельные модели поиска текста и распознавания (comic-text-detector,
  manga-ocr) не нужны в первой версии: меньше кода, нет скачивания моделей, качество зависит
  от выбранной модели. Если рамки у какой-то модели окажутся неточными, добавим свою модель
  поиска облачков (Apache-2.0, см. `PLAN.md`, раздел 2).
- **Как стирается текст.** Внутри облачка заливается светлая область вокруг текста; по каждой
  строке закрашивается промежуток между крайними светлыми точками — это закрывает буквы
  и останавливается на контуре. Красится только рядом с текстом, чтобы подпись без рамки
  на белом фоне не стёрла рисунок. Если облачко замкнуто, перевод занимает его целиком.
- **Звуковые эффекты не стираются.** Стереть их с рисунка без следов можно только нейросетью
  дорисовки (LaMa, Apache-2.0) — это отдельный шаг на будущее. Пока перевод рисуется поверх
  эффекта с белой обводкой. Перевод эффектов можно выключить.
- **Страница уходит модели как есть**, если она не больше 2048 px и 4 МБ; иначе уменьшается.
- **Перевод сохраняется** вместе с областями и текстами (`metadata`) — пригодится для
  «показать оригинал» по нажатию и для глоссария.
- **Язык по умолчанию — язык телефона**, если он есть в списке, иначе английский.
- **Проверка без ключа API — поддельный сервер** `plus/tools/fake-ai`: отвечает в формате OpenAI
  заранее записанным переводом для тестовых страниц. Так на эмуляторе проверен весь путь:
  запрос из приложения, разбор ответа, стирание, вписывание текста, кеш, контекст прошлых страниц.

**Система перевода, версия 2 (07.11)** — подробно в `plus/TRANSLATION.md`. Основано на трёх
исследованиях: научные работы по машинному переводу манги, руководства переводчиков
(VIZ, Yen Press, Kakao, Wuxiaworld, русские сканлейт-гайды, работа Туманова), цены провайдеров.
- **Библия тайтла** на каждую мангу и язык: персонажи (имя, другие формы, пол, манера речи,
  обращения), глоссарий, выбор читателя, сюжет по страницам. JSON в файлах приложения, не в кэше.
- **Первый выбор остаётся.** Модель сама сообщает новые имена и термины в ответе на страницу,
  отдельного запроса нет. Повторное предложение другого перевода того же слова отбрасывается.
  Записи, исправленные читателем, модель не меняет.
- **Запрос из трёх частей** — правила, библия, страница — в таком порядке ради кэша провайдера.
  Для Claude ставятся две отметки кэша; OpenAI и Gemini кэшируют повторяющееся начало сами.
- **«Кто говорит» с ответом «не уверен».** В память идут только уверенные ответы
  (Magi v2: без хвостика облачка угадывать нельзя).
- **Контекст страницы — последние 10 реплик с оригиналом и переводом**, а не 30 переводов:
  по исследованиям польза растёт до 7–9 реплик, и нужен оригинал. Плюс сводка прошлых страниц
  главы и трёх прошлых глав; длинную историю не шлём — она ухудшает перевод.
- **У длинных серий в запрос идут подтверждённые записи и встреченные в последних 5 главах**
  (до 40 персонажей и 150 терминов).
- **Проверки на телефоне и второй взгляд.** Остались японские, корейские или китайские знаки,
  или в переводе нет слова из глоссария (с учётом окончаний) — только эти строки уходят
  повторно, текстом без картинки. Не удалось — остаётся первый перевод.
- **Страница ждёт предыдущую до 15 секунд**, если та ещё переводится. Дольше ждать нельзя:
  иначе из двух потоков работает один. Единообразие держит библия.
- **Правила коротко и с примерами** (Yang 2024: длинные списки правил ухудшают перевод,
  примеры улучшают).
- **Русский по умолчанию:** имена — Поливанов, Концевич, Палладий (как лицензионные издания);
  «ты/вы» по отношениям, а не по суффиксу; суффиксы -кун, -тян, -сама, сэмпай, сэнсэй — где
  несут тон, через дефис, склоняется имя, а не суффикс (как у «Азбуки»); -сан обычно
  передаётся через «вы»; «ёлочки», «?!», «?..», без «!!»; «Э?» → «А?». Читатель может
  переключить на «оставлять суффиксы» или «передавать по-русски» для каждого тайтла.
- **Английские сканлейты — отдельный источник:** имена в них уже латиницей, модель
  восстанавливает их по правилам исходного языка (Sasuke → Сасукэ, а не «Саске»).
- **Узбекский — текущий алфавит** (oʻ, gʻ с U+02BB, ʼ U+02BC) до перехода на новый
  (утверждён 21.10.2026, действует с 22.04.2027: Ö, Ğ, Ş, Ç). Переход — в `FOR_ME.md`.
- **Учёт токенов на страницу** хранится вместе с переводом: из него будет цена главы в приложении.
- **Низкий уровень размышлений для страниц** (Claude 4.6+ `effort: low`, Gemini 3+ `thinkingLevel:
  low`): размышления оплачиваются как ответ, а перевод страницы — это аккуратное письмо, а не
  задача на рассуждение. Остальным моделям параметр не шлём: старые его отвергают.
- **Проверка на настоящей модели (07.11, Claude Sonnet 5.5, «Сага о Винланде», главы 127–128
  из русского издания → английский; 8 страниц → узбекский).** 56 страниц, 371 реплика, ~$0.78
  (≈$0.28 за 20 страниц, как в оценке), 5–12 с на страницу. Имена во второй главе те же, что
  в первой (Thorfinn 12 и 15 раз, других вариантов нет); глоссарий модель собрала сама
  (Thors, Floki, Jomsvikings, Jomsborg, Miklagard). Найдено и исправлено:
  - Claude отвечает координатами в пикселях картинки, а разбор ждал 0–1000 и отбрасывал всё
    ниже 1000-го пикселя — пропадали нижние облачка. Теперь у Claude просим пиксели в его
    порядке `[x1,y1,x2,y2]` и сообщаем размер картинки, у остальных — 0–1000; числа больше
    1000 читаются как пиксели в любом случае.
  - Спрошенный в порядке Gemini (`[ymin,xmin,…]`), Claude запутался и прислал второй,
    исправленный ответ; разбор теперь берёт последний правильный JSON.
  - Узбекские oʻ/gʻ модель пишет то правильным знаком, то кавычкой — телефон исправляет сам.
  - Европейские имена в узбекском — по произношению (Torfinn, не Thorfinn).
  - Кто говорит, Claude определяет приблизительно, рамки — примерно (±20–50 px, бывают меньше
    текста).
- **Вёрстка на настоящих страницах (тот же прогон, показан в приложении на эмуляторе через
  `replay_server.py`).** Найдено и исправлено:
  - замкнутое облачко стирается целиком — не остаются строки, которые рамка модели не захватила;
  - текст укладывается по форме облачка: в круглом облачке строки больше не вылезают за контур;
  - в незамкнутом облачке (обрезанном краем кадра) закрашиваются только буквы и текст ставится
    только туда — белое больше не заходит на рисунок;
  - светлые буквы на тёмном рисунке (рассказ, заголовок главы) закрываются аккуратной белой
    подложкой вместо рваных полос; надписи и таблички заменяются так же, как подписи;
  - перевод звуков рисуется мелко поверх оригинала: нарисованный звук — часть рисунка;
  - логотип серии модель не переводит.
  Осталось: два облачка, слитые «восьмёркой», иногда получают строки шире облачка; точные рамки
  дала бы своя модель поиска облачков на телефоне (план, `PLAN.md`, раздел 2).
- **Чего нет у других и что у нас лучше.** manga-image-translator, BallonsTranslator, GalTransl —
  GPL, код не брали, только идеи. У нас: страница уходит с картинкой (у них чаще только текст
  после OCR — по исследованиям хуже); имена и термины собираются из того же ответа, без
  отдельного запроса; «первый выбор остаётся» вместо перезаписи; проверка с учётом русских
  окончаний; повтор только проблемных строк текстом.

### Перевод выглядит как леттеринг оригинала (07.11)

Владелец: «очень плохо вставленный перевод очень сильно выделяется… не выбивать из погружения».
Было: системный жирный Roboto, размер в каждом облачке свой, текст по центру всего облачка
(вылезал из «восьмёрки»), белые плашки поверх надписей на рисунке.

Что сделано (код: `PageLettering`, `TextBlockLayout`, `LineBreaker`, `InkMeasure`, `ArtCleaner`,
`TextSnap`, `LetterCase`, `LetteringFonts`):
- **Шрифт Shantell Sans** (OFL 1.1, без зарезервированного имени — можно в платном
  приложении). Сравнил 7 бесплатных комиксных шрифтов с кириллицей с оригинальным леттерингом
  «Винланда»: у Shantell те же формы Д, Л, Ж; толщина 560, ширина 0.95. Pangolin и Playpen Sans
  покрывают все буквы, но выглядят как почерк, а не как леттеринг; Comic Relief и Neucha без
  казахских букв. Узбекская ʻ рисуется как ‘ (в шрифте её нет).
- **Регистр как в оригинале:** оригинал заглавными — перевод заглавными; обычный регистр
  (повествование) — обычный. У японского/китайского/корейского регистра нет — в облачках
  заглавные, как в английских и русских изданиях.
- **Размер букв как в оригинале.** Перед стиранием замеряются оригинальные буквы: строки,
  высота заглавных (или строчных), шаг строк, цвет. На странице один размер для всех облачков
  (медиана), как у леттерера; облачко с явно другим размером (крик, шёпот) — своим. Если
  замер явно ошибся (рисунок принят за буквы), берётся грубая оценка по площади рамки и длине текста.
- **Строки по форме облачка:** каждая строка шириной, какую облачко даёт на её высоте, строки
  центрированы по оси облачка (хвостик не сдвигает), блок стоит там, где был оригинал. Разбивка
  на строки — так, чтобы строки были заполнены равномерно (ромбом, как у леттерера). Уменьшается
  только если не помещается.
- **Надписи на рисунке** (повествование, заголовки): вместо белых плашек оригинальные светлые
  буквы с обводкой стираются — заполняются окружающим рисунком (только сами буквы и их чёрная
  обводка; дым, огонь, небо не трогаются) — и перевод рисуется так же: светлые буквы с тёмной обводкой.
- **Стирание надёжнее:** облачком считается только одна светлая область — та, в которой
  большая часть рамки (раньше светлые куски рисунка у края рамки заливались вместе с облачком);
  облачко, обрезанное краем страницы, считается закрытым.
- **Рамка мимо облачка** (бывает у Haiku): если под рамкой нет закрытого облачка с буквами,
  ищется ближайшее место рядом, где оно есть. Не нашлось — рисунок не трогается, перевод
  рисуется с белой обводкой.

- **Сдвоенные облачка и текст у края** (владелец прислал скриншоты 128-4 и 128-13): стиралка
  закрашивала каждую строку пикселей от первой светлой точки до последней — вместе с линией
  между двумя облачками. Теперь стирается светлая область и то, что она полностью окружает
  (буквы); линия, выходящая к контуру, остаётся. Текст ставится в свою половину облачка (по строке
  — тот кусок, где был оригинал), центрируется там, где был оригинал, и не заходит на место
  другой реплики. В открытом облачке стирание идёт по строке и на следующие строки, пока
  продолжаются буквы (рамки Haiku часто короче строки). Рамку мимо облачка переносит прямо на
  буквы найденного облачка.
- **Звуки** (позже переделано — см. «Звуки поверх рисунка перерисовываются»): перевод звука — примерно размером с оригинал (меньший перемешивался с его буквами:
  «BAM» поверх «БАМС» читалось как «EБAMC»); звук на чистом светлом фоне стирается как текст в
  облачке, на рисунке — остаётся под переводом. Слово не делится ни в звуке («ХВ/АТ»), ни в облачке
  («Попа/лся!»): сначала текст становится меньше, разрыв слова — только если не помогло и это.
- Крик с наклонными строками («NOW, MITSUBA-KUN!!»): замер склеивал строки в одну и отбрасывался,
  крик получал обычный размер страницы. Теперь без замера размер берётся из рамки и длины текста.
- Знак на щеке персонажа (封 у Ханако) Haiku перевёл как надпись «Печать». В задание добавлено:
  знаки, нарисованные на персонаже и одежде, — часть рисунка, не текст (версия задания 4).
- **Проверено и на другой манге:** «Toilet-bound Hanako-kun», т. 12 (официальное английское
  издание), 12 страниц, английский → русский, Haiku 5.5, ~$0.006 (половина страниц в этом PDF
  пустые — модель их правильно пропускает). Облачка — как оригинальный леттеринг. Слабое место —
  большие нарисованные звуки поверх рисунка («RING», «FLAP»): стереть их чисто нельзя, перевод
  ложится поверх оригинала.

Проверено на компьютере (`LetteringPreviewTest` — тот же код, рисует Java2D) на двух главах
«Винланда» с ответами Sonnet и Haiku. На эмуляторе (Android 37, экран 720×1600, ответы Haiku через
`replay_server.py`): шрифт Shantell с нужной толщиной загружается, страницы 1 и 8 выглядят как на
превью; стирание, раскладка и отрисовка — около секунды на страницу (без ответа модели, Haiku
отвечает ~10 с). На телефоне не проверено. Известные слабые места: облачко,
обрезанное краем кадра, при неточной рамке может оставить часть оригинала; подписи на карте
стираются прямоугольниками; на сложном рисунке после стирания светлых букв остаются мелкие следы.

### Звуки поверх рисунка перерисовываются (07.11)

Владелец: «Браться за большие звуки поверх рисунка?» — «Да, берись». Было: перевод звука
рисовался поверх оригинала, буквы оригинала торчали по краям («RING» под «ДЗЫНЬ»).

Что сделано (код: `SfxLetters`, `Inpaint`, `PageLettering.sfxLettering`):
- **Буквы звука находятся сами.** Звук рисуют толстыми буквами одного тона в кайме другого:
  чёрные с белой каймой или белые с чёрной обводкой. Ищутся куски этого тона, со всех сторон
  окружённые другим тоном, толстые, в основном внутри рамки модели. Тон букв выбирается так:
  не тот, у которого чернил втрое меньше (это дырки в буквах), иначе тот, что заметно толще
  (буквы толще обводки), иначе тот, где кусков примерно столько, сколько букв в тексте. Буквы
  слова за рамкой модели добираются по строке; край страницы закрывает букву, обрезанную им.
- **Стирание с дорисовкой фона.** Буквы с каймой стираются, а рисунок под ними дорисовывается
  кусочками рисунка рядом (метод Criminisi, Pérez, Toyama, 2004 — по статье, код свой):
  сначала там, где в дыру входит линия, кусочки ищутся поближе. Чтобы штриховка и растр не
  принимались за линии, «линия» — только где штрихи вокруг идут в одну сторону. Рамка кадра под
  «RING» продолжается, растр под «Baaaam» остаётся растром. Сравнивал с размыванием от краёв
  (было в `ArtCleaner`): на растре и штриховке оно даёт серое пятно.
- **Перевод рисуется как оригинал:** тот же тон и кайма той же толщины, высота букв как у
  оригинала, тот же наклон строки (направление — от буквы к соседней, уточняется по пикселям, как
  выпрямляют скан), так же на две-три строки («ХЕ / ХЕ / ХЕ», «ТОП / ТОП»). Жирность — толщина
  800, а если буквы оригинала ещё толще, они утолщаются обводкой своего цвета. Тонкий
  рукописный звук пишется обычной толщиной.
- Не нашлось букв с каймой (буквы прямо на пёстром рисунке, тонкий рукописный звук на чёрном,
  мелочь меньше 12 px) — как раньше: перевод поверх.

Попутно:
- **Сдвоенное облачко (127-10):** рамка Haiku верхней реплики была верной, но шаг «рамка мимо
  облачка → на буквы облачка» растягивал её на всё облачко вместе со второй репликой. Теперь
  рамка не переносится на буквы, где есть чужая реплика, и не растягивается, если уже стояла на
  этих буквах; рамка, внутри которой целиком лежит рамка другой реплики, обрезается.
- **Вывеска «PUMP-KIN» (Ханако, стр. 47; владелец спросил, что с надписью):** рамка Haiku
  захватила часть надписи, перевод вставал мелко внизу пустого полотна. Теперь размер текста на
  вывеске, стёртой целиком, считается по всему полотну, текст ставится в его середине. Рисунок
  тыквы на полотне при этом пропадает: отделить его от букв не вышло (касается рамки текста) —
  известная недоработка. Незакрытая вывеска стирается только в рамке, без «следования за буквами»
  (оно уходило в рисунки).
- Стёртое место в облачке закрашивается самым частым цветом бумаги, а не средним (средний
  темнее из-за краёв букв, и на сером скане был виден прямоугольник).

- Перевод звука не выходит за край страницы: строка сначала сдвигается внутрь вдоль себя,
  если места мало — уменьшается («ВУУУ» во всю ширину страницы, «B» у самого края).

Проверено на компьютере (`LetteringPreviewTest`) на 59 звуках «Винланда» и 13 звуках «Ханако»:
почти все стираются целиком и перерисовываются. Разбор страницы на компьютере — в среднем 0.56 с,
самая тяжёлая 1.8 с (больше всего времени у облачков, не у звуков). Не получается: тонкий
рукописный звук на чёрном («Brrriiing»), два звука, буквы которых слились в один кусок
(«ГУУУУЛ» над «ГУУЛ» — наклон перевода неверный), буквы, к которым прилип рисунок или рамка
кадра («ОЛ», палочка «П» у «SPLASH» на 127-3). В приложении на эмуляторе (Android 37, ответы
Haiku через `replay_server.py`) страницы 1–3 и 8 главы 127 выглядят как на превью: поворот,
утолщение и каймы рисуются Android так же. На телефоне не проверено.

### Claude Haiku 5.5 для перевода (07.11)

Владелец: «делай переводы модель haiku 5.5». Прогон двух глав «Винланда» (56 страниц, ru → en):

| | Sonnet 5.5 | Haiku 5.5 |
|---|---|---|
| Страниц без ошибок | 56 | 56 |
| Строк найдено | 371 | 365 |
| Цена за 56 страниц | ~$0.78 | ~$0.08 (вывод 116K токенов — втрое больше Sonnet) |
| Перевод | хороший | хороший, естественный; имена одинаковые (Thorfinn, Floki, Vagn) |
| Говорящий | указан часто | почти всегда «unsure» |
| Рамки | точные | медиана IoU с Sonnet 0.48; 7% рамок мимо больше чем на высоту рамки |
| Соседние облачка | раздельно | иногда два облачка одной строкой |
| Мелкие звуки | находит | часть пропускает |

Решение: по умолчанию советую Haiku 5.5 (в 10 раз дешевле, ~$0.03 за главу), неточные рамки
исправляет поиск облачка рядом (см. выше). Sonnet — для тех, кому важна каждая мелочь.


### Проверка «Берсерка» и манги Итагаки перед отправкой (08.11)

Владелец попросил перевести «Берсерк» 370–371 (34 стр.) и мангу Кэйсукэ Итагаки 370.5–370.6
(47 стр.), Haiku 5.5, en → ru: около $0.04 и $0.06. Перед отправкой просмотрел страницы и исправил:

- **Маленький колючий пузырь среди рисунка** («……!!», Берсерк 370-2) принимался за светлые
  буквы на рисунке, и стиралась большая область (серое пятно). Теперь замкнутая светлая область
  с тремя и больше мелкими тёмными пятнами внутри считается пузырём. У светлой буквы бывает одно-два
  крупных «очка» (О, В), это по-прежнему буква.
- **Реплики из одних знаков** («……!!», «……ッ!!») не трогаются: переводить нечего, оригинал
  остаётся как нарисован. Раньше Haiku писал «ч-!!», а мелкий горизонтальный «……!!» ложился
  поверх вертикального.
- **Рамка переносилась на глаз** (Берсерк 370-9). Два слипшихся пузыря не считались закрытым
  пузырём, код искал буквы рядом и принял за буквы нарисованный глаз на белой панели: глаз
  стирался, две реплики ложились одна на другую. Теперь рамку переносят только на «буквы» не
  больше 2.5× обычного размера букв на странице (медиана по пузырям, которые стоят на месте).
- **Подписи белыми буквами с обводкой прямо на рисунке** (Берсерк 370-15…17). Раньше на их месте
  было серое пятно (усреднённая штриховка) или белые кляксы (светлое вокруг букв закрашивалось
  как пузырь). Теперь их буквы сначала ищутся как буквы звуков, и рисунок под ними
  восстанавливается из соседнего рисунка; это засчитывается, если найдено от 0.75 куска на
  букву. Иначе работает прежняя очистка светлых букв, но обводка считается не толще 0.6% ширины
  страницы, и восстановление тоже идёт по рисунку, а не усреднением. Подпись, рамка которой
  меньше чем наполовину лежит в светлой области, считается подписью на рисунке.

Не исправлено:
- подписи на рисунке, у которых обводки букв слились с рисунком (меч на 370-16), стираются
  не целиком;
- у Итагаки английский текст сканлейтеров набран крупно прямо по рисунку, и местами перевод
  ложится рядом с недостёртым оригиналом;
- первая страница Итагаки (красный текст на чёрном) не стирается.

### Несколько страниц перевода одновременно (08.11)

Владелец: «может тогда сделать параллельный перевод». Страница — это один запрос к модели;
почти всё время уходит на ожидание сервера, поэтому страницы главы теперь переводятся
по несколько одновременно.

- У шага обработки (`PageProcessor`) есть `concurrency`: сколько страниц он берёт одновременно
  (по умолчанию 2, у перевода 4). Движок держит общий лимит в 4 страницы и до 8 в очереди.
- Связность перевода. Пока у тайтла нет заметок (имён, терминов), страница ждёт предыдущую,
  как раньше: первые страницы задают имена. Дальше страницы идут параллельно, и каждая видит
  заметки, а не текст предыдущей страницы.
- Замер на «Берсерке» 370 (17 стр., Haiku 5.5, en → ru), всё время на главу:

| Одновременно | Время | Цена |
|---|---|---|
| 1 | 148 с | одинаковая (вход ~97K, вывод ~27K токенов) |
| 4 | 50 с (в 3 раза быстрее) | та же |
| 8 | 44 с | та же |

Выбрано 4. Восемь дают лишь 12% выигрыша, а имя поплыло: на стр. 3 «Шиерке», на 5 и 9
«Ширке» (страницы шли одновременно, имя ещё не попало в заметки). Больше 4 упирается в лимиты
запросов у провайдера, тем более на бесплатных ключах. Позже можно подбирать число
по заголовкам лимитов в ответе.

Ещё: если оригинальная строка не в кавычках, а перевод модели целиком в кавычках
(«Леди Фарнезе...!!»), кавычки снимаются.

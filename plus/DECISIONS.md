# Решения, принятые без владельца

С 07.11.2026 три модуля (перевод, улучшение сканов, раскраска) делаются без ожидания ответов.
Если что-то неясно, Claude выбирает сам и записывает решение сюда: что решено, почему и что
придётся переделать, если владелец решит иначе. То, что без владельца не сделать, — в `FOR_ME.md`.

Решения до 07.11.2026 — в таблице `PLAN.md`.

## Общее

- **Где лежат файлы.** `DECISIONS.md` и `FOR_ME.md` — в `plus/`, рядом с `PLAN.md`: весь наш код
  и документы живут в `plus/`.
- **Ветки.** Общая основа — ветка `relad/core` от `main`. Модули — `relad/translate`,
  `relad/enhance`, `relad/colorize`, каждая от `relad/core`. В `main` ничего не вливаю: это
  решение за владельцем (порядок — в `FOR_ME.md`). Ветки отправляю на GitHub, чтобы они не
  жили только на одном компьютере.
- **Список «15 пунктов» не пришёл.** В сообщении вместо него стоял текст «[список из 15 пунктов]».
  Архитектуру строю с учётом идей из `PLAN.md`: чтение по кадрам, глоссарий, правки сообщества,
  редкие языки, пересказ, персонажи, сервер и подписка, легальные источники. Если в списке
  есть что-то ещё, проверю архитектуру, когда список придёт.
- **M1 заменён веткой основы.** План M1 от 06.11 (экран, настройки, доступ к странице, слой)
  остаётся, но делается в объёме, который нужен трём модулям.
- **Главный механизм — обработка картинки страницы, а не слой поверх.** Все три функции
  устроены одинаково: «взять картинку страницы → получить новую картинку». Перевод рисуется
  прямо на копии страницы поверх оригинала, улучшенная и раскрашенная страница заменяют
  исходную. Почему:
  - приближение, прокрутка, режимы «страницы» и «лента» работают сами, ничего не съезжает;
  - не зависит от того, как Mihon рисует страницу (переживёт его будущий рендерер);
  - один кеш и одна очередь для всех трёх функций, функции можно сочетать
    (раскрасить → улучшить → перевести).

  Минус: на переведённой странице нельзя нажать на облачко и увидеть оригинал. Для этого
  позже добавим слой поверх страницы, данные для него (области и тексты) сохраняются уже сейчас.
- **Страница показывается сразу.** Сначала открывается оригинал, обработанная версия
  подменяет его, когда готова. Поэтому медленный перевод или улучшение не задерживают чтение.

## Основа (ветка `relad/core`)

- **Конвейер.** Шаги идут по порядку: раскраска → улучшение → перевод. Раскрашиваем
  до увеличения, потому что облачная раскраска отдаёт картинку ~1000 px и дешевле на маленькой
  странице. Переводим последним, чтобы текст рисовался на финальной, самой чёткой странице.
- **Кеш каждого шага отдельно** (300 МБ, старые удаляются первыми). Выключил перевод — сразу
  видна улучшенная страница, без повторной обработки.
- **Очередь «новые первыми».** Страница, которую открыли последней, — та, на которую смотрят.
  Ждут не больше 6 задач, лишние отбрасываются и запрашиваются снова, когда страница
  откроется. Одновременно — 2 задачи.
- **Ошибка не повторяется минуту** (или до смены настроек), чтобы глава без ключа API не слала
  запросы по кругу. Ошибка видна всплывающим сообщением, не чаще раза в 10 секунд.
- **Анимированные страницы (GIF, анимированный WebP) не обрабатываются.** Их нельзя
  перерисовать без потери анимации.
- **Свой HTTP-клиент для ИИ, не клиент Mihon.** В подробном сетевом журнале Mihon печатаются
  заголовки запросов, а в них ходят ключи Gemini и Claude. Плюс куки и кеш Mihon — для сайтов
  манги, ИИ они не нужны.
- **Ключи API — в Android Keystore (AES-GCM), в закрытой настройке.** В бэкап Mihon не
  попадают; системный бэкап на другой телефон их не расшифрует. У TachiyomiAT ключи лежали
  открытым текстом и попадали в бэкап.
- **Три формата API без SDK:** OpenAI Chat Completions (OpenAI, OpenRouter, локальные серверы),
  Gemini `generateContent`, Anthropic Messages. Официальные REST API, никаких
  неофициальных адресов. TachiyomiAT использовал неофициальный `translate.google.com`
  и архивированный SDK Gemini.
- **В запросы OpenAI-формата не отправляются `temperature`, `max_tokens` и `response_format`.**
  Новые модели OpenAI отвергают часть из них, многие модели OpenRouter — остальные. Формат
  ответа описывается в самом запросе, JSON достаётся из ответа даже с лишним текстом вокруг.
- **Claude: запасная модель при отказе.** Новые модели Claude (Opus 5.5, Opus 5, Sonnet 5.5,
  Fable 5.1) могут отклонить запрос своими фильтрами безопасности (ответ 200 со
  `stop_reason: "refusal"`). На API Anthropic таким моделям добавляется `fallbacks: "default"`
  (бета `server-side-fallback-2026-07-01`): отклонённый запрос сам перезапускается на модели,
  которую Anthropic советует для этого вида отказа. Для прокси и других моделей не добавляется.
  Если отказали все — пользователь видит «Claude отклонил запрос (категория)», а не «пустой ответ».
- **Модели в провайдере не выбраны заранее.** Пользователь пишет ID модели сам: список моделей
  меняется каждый месяц, а зашитое в код быстро устаревает (у TachiyomiAT по умолчанию стояла
  уже отключённая `gemini-1.5-pro`).
- **Функции включаются глобально, не для каждой манги.** Включение по манге и быстрый
  переключатель в читалке — следующий шаг, данные для этого готовы.
- **Тестовая манга — синтетическая** (`plus/tools/test-manga`), чтобы не было вопросов
  с авторскими правами.

## Чтение по кадрам (ветка `relad/panels`)

Владелец попросил отдельным модулем: приложение само находит кадры, показывает по одному
кадру на весь экран, свайп — следующий кадр, после последнего — следующая страница. Порядок
зависит от направления чтения, длинные страницы вебтунов делятся на куски. Включается в читалке
и в настройках Re:Lad. Ветка `relad/panels` от `relad/core`.

**Что сделали мы и почему так:**
- **Классический разбор картинки, без модели.** Работает сразу и без интернета, ничего не
  скачивается, нет вопросов к лицензии весов. На компьютере ~20 мс на страницу; на эмуляторе
  в отладочной сборке 0,1–0,9 с (в фоне, заранее для соседних страниц). Результат кешируется.
  Единственная разрешённая готовая модель (DeepPanel) не даёт порядка и тянет TensorFlow Lite.
  Если классики не хватит, обучим свою модель (RF-DETR N/S/M/L или D-FINE — Apache-2.0,
  датасет Manga109-s разрешает коммерцию с указанием) — см. `FOR_ME.md`.
- **Как ищем (`plus/panels`, `PanelDetector`):** цвет полей берём с краёв страницы (белые или
  чёрные); поле «заливаем» от краёв страницы, заранее закрыв разрывы рамок до 2 px; всё, куда
  заливка не дошла, — кадры. Кусок, который на самом деле два кадра, склеенных облачком через
  поле, разрезаем по полосе, где почти одно поле, но только если обе половины похожи на кадры
  (так не режем персонажа «по шее»). Мелочь (номер страницы, пылинки) отбрасываем.
  Работаем на копии ~1100 px, поэтому толщина полей у всех страниц похожа.
- **Страницы, где кадр уходит за край листа** (у других — «ничего не нашли»): если по краям
  нет явного цвета полей, пробуем белый, потом чёрный, и принимаем, только если вышло ≥2
  непересекающихся кадра на ≥55 % страницы. **Тёмные страницы:** кадр между чёрными полями —
  светлый прямоугольник; тёмный рисунок на чёрном (титры) не режем на куски.
- **Порядок (`ReadingOrder`):** страницу режем прямыми линиями, которые не задевают кадры:
  сначала ряды сверху вниз, внутри ряда — справа налево (манга) или слева направо (комиксы),
  и так дальше вглубь. Высокий кадр рядом с двумя низкими читается как колонка. Наклонные
  кадры немного залезают на соседей — линии разрешено задеть края кадров (по 15 %).
  **Развороты** читаем постранично: сначала правая страница для манги. Если прямой линии нет
  (кадры «вертушкой») — сверху вниз, при равной высоте по направлению.
- **Направление — из режима читалки:** «справа налево» → RTL, «слева направо» → LTR; в
  вертикальных режимах — RTL для японских источников, иначе LTR. В настройках можно задать явно.
- **Рамки не в конвейере страниц, а в своём кеше** (`PanelStore`: JSON по хешу картинки,
  в памяти и на диске, 3000 файлов). Подсказка из задания (процессор, который возвращает
  страницу без изменений) не подошла: конвейер хранит картинки, и шаг «кадры» хранил бы вторую
  копию каждой страницы; страница на экране перезагружалась бы ради рамок; `metadata()`
  конвейера отдаёт данные только последнего шага и спрятало бы данные перевода; а если поставить
  кадры первым шагом, их переключение сбросило бы кеш перевода и улучшения.
- **Кадры ищутся на той картинке, которую читалка правда показывает** — после перевода,
  улучшения, а также разрезания разворотов и поворота Mihon. Поэтому рамки совпадают. Когда
  приходит обработанная версия страницы, читатель остаётся на том же кадре.
- **В режимах «страницы»:** кадр приближается на весь экран с плавной анимацией, всё вокруг
  затемняется (Mihon не даёт сдвинуть страницу за край, поэтому соседние кадры видны —
  затемнение убирает отвлечение). Свайп, нажатие по краю, клавиши громкости — следующий кадр,
  после последнего — следующая страница. Соседние страницы заранее стоят на первом
  (или последнем) кадре, так что перелистывание едет от кадра к кадру. Щипок приближает
  как обычно; если приблизил сам — пальцем можно двигать страницу. Кадр, который сильно выше
  экрана (вебтун, открытый страницами), показывается по ширине в несколько шагов с перекрытием
  12 %. Слишком маленький кадр приближаем не больше чем в 4 раза. «Приближение широких страниц»
  Mihon в режиме кадров отключается (оно перебивало бы кадр), «обрезка полей» Mihon
  учитывается (повторяем её расчёт, чтобы рамки совпали).
- **В режимах «лента»:** полоса режется на экраны по пустым полосам между кадрами. «Далее»
  ставит наверх первый кадр, который обрезан нижним краем экрана; полностью видимые уже
  прочитаны; длинная пустота пропускается; кадр, который продолжается на следующей картинке,
  не режется по границе картинок; кадр выше экрана листается по экрану с перекрытием. Свайп
  тоже ведёт к следующему куску (как перелистывание), короткое движение возвращает обратно.
  Где ещё ничего не известно (страница грузится) — обычная прокрутка Mihon.
- **Включение:** кнопка в нижней панели читалки (подсвечена, когда режим включён) и пункт
  «Чтение по кадрам» на экране Re:Lad с настройками: порядок кадров, «сначала вся страница»,
  затемнение. Режим общий, не для каждой манги (как остальные функции).
- **В общий код основы (`PlusFeature.kt`, `Plus.kt`, правка на этой ветке) добавлено
  `PlusFeature.processesPages`:** функции, которые не меняют картинку страницы. Они не входят
  в конвейер, их переключение не перезагружает страницы.
- **Правки Mihon — 6 файлов** (см. `HOOKS.md`): касания пейджера, переход к кадру вместо
  страницы, начало страницы, картинка страницы (2 вида читалки), прокрутка ленты, кнопка.

- **Не проверено:** телефон владельца (скорость в выпускной сборке), альбомная ориентация,

**Слабые места (честно):**
- Крупные звуковые эффекты или рисунок поверх полей со всех сторон («Бек»: концерты,
  вертолёт) — кадры не разделяются, страница показывается целиком. Из 255 страниц целиком
  показаны 31, из них около половины — обложки, сплэши и титры (это правильно).
- У наклонного кадра затемнение по прямоугольнику: уголки соседей не затемнены.
- Кадры без полей между ними (общая линия рамки) находятся как один кадр.
- Титры с фигурами на белом могут разбиться на 2 «кадра».
- Если когда-нибудь понадобится точнее — своя модель (см. `FOR_ME.md`).
